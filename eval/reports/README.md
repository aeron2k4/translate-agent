# Benchmark reports

Generated by `make benchmark` on the synthetic golden set (231 cases). Each report
holds numbers and case ids only.

| Report | What |
| --- | --- |
| `benchmark-mock` | Mock provider: checks the mechanics only |
| `benchmark-river-baseline` | Real model (OpenAI-compatible endpoint, fast and strong tier on the same model) before the fixes below |
| `benchmark-river` | Same model after the fixes |

## Fixes measured

1. **Speaker roles.** Vietnamese kinship words (anh/chị/em) mean both "I" and "you". Address forms are
   now inferred from vocatives, remembered per member with the thread TTL, and the prompt states
   the sender's and the reader's form.
2. **Masked counts.** The prompt names each placeholder's type (`⟦E1⟧ = number`) so the model
   keeps the words around it ("Xe ⟦E1⟧ chỗ" → "⟦E1⟧-seat car").

Case level: 24 → 19 messages with a major or critical error; 9 fixed, 4 new, 15 unchanged.

- Fixed by the changes: `vi04` ×4 and `ctx08` (speaker roles), `vi34-1`, `vi34-2` ("Xe ⟦E1⟧ chỗ").
- `vi31-1` ×2 also changed although the fixes do not touch them: judge and model are not deterministic,
  so differences of one or two messages per group are noise.
- Thread context recall stays at 94.1% because it measures the message window only; `ctx08` is
  now fixed by the remembered address forms, not by the window.
- New: `vi34-*-chat` (unaccented "cho" read as "for", not "chỗ"), `vi12-1-unaccented` and
  `vi30-2-unaccented` (no vocative, so no address cue).

## Remaining causes

- "Cọc ⟦E1⟧ xe" is still read as a deposit amount ("a 2 deposit on the car"); showing the small count's
  value next to the type was tried and did not help.
- Domain terms missing from the glossary ("bấm biển số" = plate issued) and unaccented words
  ("chenh" = chênh).
- Messages with two address forms and no vocative ("Em gọi anh số … nhé") are genuinely ambiguous.
- Latency is above target (TTFT p95 > 1.2 s) and the strong tier takes ~28% of traffic (target 10–20%).
